# Reasoning

## Overview

Apply specific structured thinking tools to complex problems before deciding or acting.

**Core principle:** Name your assumptions before reasoning from them. A confident conclusion built on unexamined assumptions is just confident noise.

**Distinction from related skills:**
- `thinking-partner` — how to *engage* (modes: opinion, challenge, ideation, sounding board)
- `decision-making` — making a choice between named options with structured scoring
- `reasoning` — *thinking tools* to clarify the problem itself before deciding

---

## The Toolkit

Use one or more of these tools based on what the problem needs:

---

### First Principles Decomposition

**Use when:** A problem looks complex because it's built on unexamined assumptions. Break it to fundamentals and rebuild.

**Process:**
1. State the problem or belief as currently understood
2. Ask: "What would have to be true for this to be the only approach?"
3. List every assumption embedded in the current framing
4. For each assumption: is it actually true, or just inherited convention?
5. Rebuild from what's genuinely true, not what's assumed

**Signal that you need this:** You're solving a problem the same way it's always been solved, and no one can remember why.

---

### Pre-Mortem

**Use when:** About to commit to a plan or decision. Stress-test it before committing.

**Process:**
1. Assume it's 6 months from now and the plan failed
2. Ask: "What went wrong?" — generate all plausible causes, not just the comfortable ones
3. For each failure mode: how likely? how catastrophic? how detectable early?
4. Identify which failure modes the current plan doesn't account for
5. Decide: adjust the plan, or proceed knowing the risk?

**Output:** A ranked list of failure modes with likelihood and mitigation. Not a reason to stop — a reason to prepare.

---

### Assumption Mapping

**Use when:** About to build something, make a recommendation, or draw a conclusion. Make implicit assumptions explicit before acting on them.

**Process:**
1. State the plan, recommendation, or conclusion
2. List every assumption it depends on — be exhaustive
3. For each assumption: rate it
   - **Known fact** — verifiable, not really an assumption
   - **Reasonable belief** — likely true, but check it
   - **Leap of faith** — uncertain, outcome depends heavily on this
4. For each "leap of faith": what would you do if it turned out to be wrong?
5. Identify: which assumptions, if wrong, would invalidate the whole thing?

**Signal that you need this:** You're confident about a plan but haven't written down what you're betting on.

---

### Inversion

**Use when:** Trying to achieve something positive. Instead of planning for success, plan against failure.

**Process:**
1. State the goal: "I want X"
2. Invert: "What would guarantee NOT-X?"
3. Generate a comprehensive list of things that would cause failure
4. Remove or avoid those things as the primary strategy
5. What remains after removing failure conditions is the path forward

**Signal that you need this:** Positive planning keeps producing plans that look good on paper but fail in practice.

---

### Devil's Advocate

**Use when:** Everyone agrees and it feels too easy. Or when a strong opinion needs its blind spots identified.

**Process:**
1. State the consensus view or plan
2. Steelman it: what's the strongest version of this argument?
3. Now argue against the steelmanned version — find the real objections
4. Distinguish: objections that break the argument vs. objections that refine it
5. Update the plan with valid objections incorporated

**Rules:**
- Steelman first (find the best version) before attacking
- Argue against your own position as hard as you'd argue against a bad idea
- Objections that survive scrutiny are findings — incorporate them

---

## Selecting the Right Tool

| Situation | Tool |
|-----------|------|
| "Why are we doing it this way?" | First Principles |
| "Are we sure this will work?" | Pre-Mortem |
| "What are we assuming?" | Assumption Mapping |
| "How do we avoid failure?" | Inversion |
| "Is this actually right?" | Devil's Advocate |

You can combine: run Assumption Mapping, then Pre-Mortem on the highest-risk assumptions.

---

## Output

After applying the tool(s), produce:
1. **Findings** — what the analysis revealed that wasn't obvious before
2. **Changed conclusions** — what you'd do differently as a result
3. **Open questions** — what still needs to be answered

If the analysis changed nothing: that's a valid output. "We examined the assumptions and they held up" is a useful finding.

---

## Common Failures

| Failure | What it looks like | Fix |
|---------|--------------------|-----|
| **Performing the process** | Going through the steps without actually challenging anything | If your pre-mortem found no failure modes, you didn't try hard enough |
| **Confirmation bias** | Devil's advocate that agrees with you | The steelman must be as strong as you can make it |
| **Paralysis** | Using reasoning tools to delay deciding | Reasoning is a precursor to action, not a substitute |
| **Assumption creep** | Listing only the assumptions you're confident about | "Leaps of faith" are the ones that matter — find them |
